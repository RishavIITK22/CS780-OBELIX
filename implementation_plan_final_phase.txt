1. Recurrent latent directly inside the policy
Simplest baseline.

Idea:

feed raw 18-bit observations, previous action, maybe previous reward
let an LSTM/GRU learn an internal hidden state
actor/critic use that hidden state for action/value prediction
Why this works:

the recurrent hidden state becomes the latent belief state
no separate encoder training objective is needed
For OBELIX:

this is the easiest learned-latent approach
probably the first thing to try before more complex world-model methods
Input suggestion:

obs_t
prev_action_one_hot
maybe prev_reward_scaled
This is basically “learned belief state through recurrence”.

2. Learned observation encoder + recurrent belief model
Better structured.

Idea:

z_t = f(obs_t) from an MLP encoder
recurrent update:
h_t = GRU(h_{t-1}, [z_t, a_{t-1}])
actor/critic use h_t
This separates:

observation compression
memory / belief update
Why it’s better than raw-LSTM:

cleaner representation learning
easier to inspect and reuse
easier later if you want auxiliary losses
For OBELIX, this is probably the best medium-complexity design.

3. Predictive latent model / world model
Most principled, more complex.

Idea:
learn a latent state s_t such that it is useful to predict:

next observation
reward
done
maybe next latent
Then policy acts on s_t.

Typical training losses:

reconstruction loss: obs_t -> latent -> obs_t_hat
dynamics loss: (s_t, a_t) -> s_{t+1}
reward prediction loss
done prediction loss
For a POMDP, better version is:

deterministic hidden state h_t
stochastic or deterministic latent summarizing history
This is closer to:

world models
Dreamer / RSSM-style ideas
predictive state representations
For OBELIX, this can work well, but it is a bigger engineering jump.

4. Contrastive / self-supervised latent
Use auxiliary losses to learn a useful latent without full reconstruction.

Examples:

inverse dynamics: from (z_t, z_{t+1}) predict a_t
forward dynamics: from (z_t, a_t) predict z_{t+1}
CPC / contrastive predictive coding across time
This is attractive for OBELIX because:

observations are tiny
the important thing is action-relevant latent structure
you may not need full decoder reconstruction
This is a good middle ground if you want a learned latent richer than hand-coded features.







So you can absolutely avoid hand-coded shaping and still make progress.

Best alternatives

1. Curiosity / intrinsic reward
This is the strongest replacement for manual shaping.

Instead of saying:

“give +x for alignment”
“give +y for moving forward”
you let the agent get reward for discovering transitions that are novel or hard to predict.

For OBELIX this is especially useful in the find phase.

Good choices:

ICM-style forward prediction error
RND-style novelty bonus
count-based bonus on encoded states
This is the most direct non-handcrafted replacement.

2. Auxiliary learning tasks
Keep the extrinsic reward sparse, but learn better representations from extra prediction tasks.

Examples:

predict next observation
predict reward
predict done
inverse dynamics: infer action from consecutive observations
predict whether box is likely visible / whether stuck will occur next
This does not change the reward, but it makes PPO learn much better from sparse returns.

This is often easier to stabilize than curiosity rewards.

3. Hindsight / relabeling-style ideas
If the task has useful intermediate events, you can define learned subgoals or relabeled targets.

For OBELIX, examples of pseudo-subgoals:

first box visibility
first IR contact
sustained contact
box reaches boundary
This starts becoming a goal-conditioned RL setup.
It is possible, but more engineering-heavy than curiosity or auxiliary tasks.

4. Curriculum learning
Instead of shaping reward, shape the training distribution.

Examples:

start with static box, no wall
then add wall
then blinking box
then moving+blinking
or start with easier spawn distributions where robot and box are closer
